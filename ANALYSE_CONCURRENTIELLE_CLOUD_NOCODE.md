# Analyse concurrentielle — Caelum vs géants du cloud & plateformes no-code

> Revue : 2026-06-29. Objectif : identifier le **vrai** avantage concurrentiel, valider l'adéquation
> produit/marché, **éviter les fonctionnalités superflues** et garantir le ROI. Honnête.

---

## 1. Bien cadrer : qui est vraiment un concurrent ?

| Catégorie | Exemples | Est-ce un concurrent ? |
|---|---|---|
| **Géants du cloud** | AWS, Azure, Google Cloud, Vercel, Cloudflare | ❌ **Non — ce sont des fournisseurs.** Ils vendent l'infrastructure, pas le métier conformité belge. |
| **Plateformes no-code** | Bubble, Webflow, Airtable, Softr, Glide | ⚠️ **Outils, pas produit.** N'importe qui peut bâtir un formulaire ; personne n'a notre **contenu juridique vérifié**. |
| **RegTech verticaux / GRC** | OneTrust, Vanta, Drata, éditeurs e-facture | ✅ **Vrais concurrents** (mais mono-sujet, chers — cf. veille). |
| **Logiciels comptables / fiduciaires** | WinBooks, Exact, Odoo | ✅/🤝 Concurrents **et** partenaires (canal). |
| **Consultants conformité** | cabinets, Big Four | ✅ Concurrents (chers, « vendent la peur »). |

➡️ **Erreur à éviter** : se comparer aux géants du cloud comme à des rivaux. Ils sont notre **socle technique** (cf. étude infra). Le vrai terrain de jeu, c'est le **vertical conformité belge**.

## 2. Pourquoi cloud & no-code ne sont PAS notre moat (ni notre menace principale)

- **Le cloud est une commodité** : tout le monde y a accès. Construire dessus ne donne aucun avantage durable.
- **Le no-code abaisse la barrière technique** : un concurrent pourrait **cloner notre interface** (un simulateur, un formulaire) en quelques jours.
- **Donc la technologie n'est PAS défendable.** Si notre seul atout était « un beau simulateur », il serait copiable. Ce n'est pas là qu'est la valeur.

## 3. Notre VRAI avantage concurrentiel (le moat)

Ce qui est **difficile à répliquer**, même avec tous les outils cloud/no-code du monde :

1. **Corpus juridique belge vérifié et sourcé** (143 modules / 459 réponses citoyennes + 17 normes B2B, chacune **loi en vigueur + source officielle tier1 + date**). Le construire et le **maintenir à jour** est un travail continu — c'est ça, la barrière à l'entrée.
2. **Conformité finançable** : la cartographie **obligation ↔ aide publique régionale** (chèques Wallonie, kmo-portefeuille Flandre). Quasi personne ne le fait.
3. **Confiance & honnêteté locales** : positionnement « sourcé, daté, non anxiogène » ↔ le marché rejette la peur (cf. veille). Trust Center, plateforme qui s'auto-audite.
4. **Canal fiduciaires marque blanche** : distribution via les cabinets ITAA (effet de levier).
5. **Bilingue/local belge** (FR/NL + EN), régionalisé là où il le faut.

➡️ **Moat = DONNÉES + CONFIANCE + DISTRIBUTION**, pas l'infrastructure. C'est défendable car cumulatif (chaque domaine vérifié, chaque cabinet partenaire renforce l'avance).

## 5. Anti-fonctionnalités superflues (ce qu'on ne doit PAS construire)

| Tentation | Verdict | Pourquoi |
|---|---|---|
| Refaire de l'infrastructure (hébergement, file, auth maison) | ❌ | Le cloud le fait mieux/moins cher (build vs buy) |
| Devenir un **access point Peppol** | ❌ | Cher, audité, hors moat → **orienter** via comparateur neutre |
| Bâtir un **GRC complet** (ROPA/DSAR/DPIA workflows) | ❌ | OneTrust/Vanta le font ; rester la **porte d'entrée** + partenariats |
| Un **constructeur no-code** | ❌ | Hors métier |
| Sur-ingénierie technique | ❌ | La valeur est dans le **contenu**, pas le code |
| **Enrichir le corpus + financement + canal fiduciaires** | ✅ | C'est le moat → tout le ROI est là |

## 6. ROI : règle build vs buy

- **Acheter/louer** (commodités, non différenciant) : hébergement (Cloudflare/UE-natif), e-mail, DNS, formulaires, paiement. Coût infra **négligeable** (cf. étude infra : ~0-80 €/mo).
- **Construire** (différenciant, le moat) : corpus vérifié, mapping aides, contenu, simulateur, canal fiduciaires.
- **ROI optimal** = ne dépenser le temps de dev que sur le moat ; tout le reste = briques cloud bon marché. Marge SaaS 75-85 % préservée.

## 7. Risques & angles morts
- **Réplication du contenu** : un concurrent pourrait copier des fiches → mitigation = **fraîcheur** (veille juridique), profondeur, et le **mapping aides** (plus dur à copier).
- **Désintermédiation par un géant** (peu probable sur un marché belge de niche, peu rentable pour eux).
- **Dépendance fournisseur cloud** : garder la **portabilité** (Next.js standard, données exportables, UE-natif possible).

## 8. Conclusion
Notre avantage **n'est pas technologique** (le cloud/no-code commoditisent la tech) mais **vertical** : **corpus belge vérifié + conformité finançable + confiance + canal fiduciaires**. Le produit colle aux **douleurs réelles validées**. ROI maximal = **acheter les commodités, construire le moat**, et **ne pas** dériver vers l'infra, le GRC lourd ou l'access point Peppol. Les géants du cloud sont nos **fournisseurs**, pas nos rivaux ; les vrais concurrents (RegTech mono-sujet, consultants chers) laissent vide l'espace « simple + sourcé + finançable + honnête » que nous occupons.
