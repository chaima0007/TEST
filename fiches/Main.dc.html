Rocky 9 face à Ubuntu/Debian

Même travail, deux syntaxes. Première cause d'erreur quand on suit les deux cours en parallèle : la commande est juste, la distribution est fausse.

Les équivalences à connaître

Besoin
Rocky 9 / RHEL
Ubuntu / Debian
Installer un paquet
le nom du paquet change aussi
sudo dnf install httpd
sudo apt-get install -y apache2
Rafraîchir l'index
sudo dnf makecache (auto à l'expiration)
sudo apt-get update
Créer un compte
sudo useradd -m paul puis sudo passwd paul
sudo adduser paul (interactif)
Groupe qui donne sudo
wheel
sudo usermod -aG wheel paul
sudo
sudo usermod -aG sudo paul
Unité systemd de SSH
sshd
systemctl status sshd
ssh
systemctl status ssh
Pare-feu
firewalld — firewall-cmd (zones, runtime)
ufw — sudo ufw allow 22/tcp
Réseau permanent
nmcli (NetworkManager)
netplan — /etc/netplan/*.yaml (Ubuntu)
/etc/network/interfaces (Debian)
Journaux — authentification
puis général
/var/log/secure
/var/log/messages
/var/log/auth.log
/var/log/syslog
Dépôts déclarés dans
/etc/yum.repos.d/
/etc/apt/sources.list.d/
Droits par défaut — dossier personnel
puis /etc/ssh/sshd_config
drwx------ (0700)
-rw------- (600) — sudo requis
drwxr-x--- (0750)
-rw-r--r-- (644) — lisible par tous

Ce qui ne change pas

ip a ip route ssh scp systemctl journalctl grep find tar chmod lsblk mount — et le processus s'appelle sshd des deux côtés, même quand l'unité s'appelle ssh. Toujours -aG, jamais -G : sans le a, l'utilisateur est retiré de tous ses autres groupes.

Le piège le plus fréquent
$ systemctl status ssh # sur Rocky Unit ssh.service could not be found.
Tu es sur Rocky : l'unité s'appelle sshd, et ssh n'existe pas. L'inverse n'est pas vrai — sur Ubuntu, systemctl status sshd fonctionne quand même, parce que ssh.service déclare sshd comme alias. Le sens qui échoue est donc toujours le même : ssh sur Rocky.
