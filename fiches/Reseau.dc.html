Réseau, SSH et SCP

Du plus proche au plus lointain : chaque étape ne devient interprétable que si la précédente est bonne.

Diagnostic — toujours dans cet ordre

1
ip a  Ai-je une adresse ? Pas d'adresse → inutile de tester la suite.
2
ip route  Ai-je une passerelle ? Pas de ligne default via → la machine ne sort pas de son réseau.
3
ping -c3 192.168.0.254  La passerelle répond-elle sur le réseau local ?
4
ping -c3 8.8.8.8  Le routage sort-il ? Une IP pure, jamais un nom : sinon l'échec ne dit pas si c'est le réseau ou le nom.
5
getent hosts rockylinux.org  La résolution de noms répond-elle ? Étape 4 bonne + étape 5 muette = problème DNS, rien d'autre.

Deux outils, deux portées

ip — immédiat, perdu au redémarrage
sudo ip link set ens18 up sudo ip addr add 192.168.0.10/24 dev ens18 sudo ip route add default \ via 192.168.0.254 dev ens18
nmcli — écrit dans le profil
nmcli connection show # le NOM du profil sudo nmcli connection modify ens18 \ ipv4.method manual \ ipv4.addresses 192.168.0.10/24 \ ipv4.gateway 192.168.0.254 sudo nmcli connection up ens18

modify écrit, up applique — l'oubli du up est la première cause du « rien ne change ». Et modify porte sur le nom du PROFIL, pas de l'interface : il peut s'appeler « System ens18 ». DNS : ipv4.dns "192.168.0.254 1.1.1.1", guillemets obligatoires · DHCP : ipv4.method auto · filet pointillé = volatil.

SSH et SCP

ssh chaima@192.168.0.10 ouvrir une session distante
ssh -p 2222 chaima@192.168.0.10 port autre que 22
ssh chaima@192.168.0.10 "hostname" une commande, sans session
scp rapport.txt chaima@192.168.0.10:/home/chaima/ envoyer
scp chaima@192.168.0.10:/home/chaima/notes.txt . rapatrier (le point = ici)
scp -r labo3/ chaima@192.168.0.10:/home/chaima/ un dossier
scp -P 2222 rapport.txt chaima@192.168.0.10:/home/chaima/ autre port
Les pièges qui coûtent des points
  • ssh -p minuscule, scp -P majuscule. Pour scp, -p minuscule signifie « conserver dates et droits » : la commande passe, mais pas sur le bon port.
  • Un dossier sans -r : scp: labo3: not a regular file. Et sans les deux-points avant le chemin distant, scp traite la cible comme un chemin local : rien ne part sur le réseau.
  • Après avoir modifié sshd_config : sudo sshd -t pour valider la syntaxe, puis sudo systemctl restart sshd — service sshd sur Rocky, ssh sur Ubuntu. Sans le restart, l'ancienne configuration reste en mémoire.
