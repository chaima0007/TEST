Réseau, SSH et SCP

Le diagnostic va du plus proche au plus lointain : chaque étape ne devient interprétable que si la précédente est bonne.

Diagnostic — toujours dans cet ordre

1
ip a  Ai-je une adresse ? Pas d'adresse → inutile de tester la suite.
2
ip route  Ai-je une passerelle ? Pas de ligne default via → la machine ne sort pas de son réseau.
3
ping -c3 192.168.0.254  La passerelle répond-elle sur le réseau local ?
4
ping -c3 8.8.8.8  Le routage sort-il ? Une IP pure, jamais un nom : sinon l'échec ne dit pas si c'est le réseau ou le DNS.
5
getent hosts rockylinux.org  Le DNS répond-il ? Étape 4 bonne + étape 5 muette = problème DNS, rien d'autre.

Deux outils, deux portées

ip — immédiat, perdu au reboot
sudo ip link set ens19 up sudo ip addr add 192.168.20.10/24 dev ens19 sudo ip route add default \ via 192.168.0.254 dev ens18
nmcli — écrit dans le profil
sudo nmcli connection modify ens18 \ ipv4.method manual \ ipv4.addresses 192.168.0.1/24 \ ipv4.gateway 192.168.0.254 sudo nmcli connection up ens18

modify écrit, up applique — oublier le up est la cause n°1 du « rien ne change ». DNS : ipv4.dns "192.168.0.254 1.1.1.1", guillemets obligatoires. DHCP : ipv4.method auto.

SSH et SCP

Ce que je veux faire
Commande
Ouvrir une session distante
ssh chaima@192.168.0.10
Port autre que 22
ssh -p 2222 chaima@192.168.0.10
Une commande, sans session
ssh chaima@192.168.0.10 "hostname"
Envoyer un fichier
scp rapport.txt chaima@192.168.0.10:/home/chaima/
Rapatrier un fichier
scp chaima@192.168.0.10:/home/chaima/notes.txt .
Envoyer un dossier
scp -r labo3/ chaima@192.168.0.10:/home/chaima/
Copier sur un autre port
scp -P 2222 rapport.txt chaima@192.168.0.10:/home/chaima/
Les pièges qui coûtent des points
  • ssh -p en minuscule, scp -P en majuscule. Pour scp, -p minuscule veut dire « conserver dates et droits » : la commande passe, mais pas sur le bon port.
  • Un dossier sans -r : labo3: not a regular file.
  • Oublier les deux-points avant le chemin distant : scp copie en local sans rien dire. Et modifier sshd_config sans systemctl restart sshd ne change rien : le service garde l'ancienne configuration.
  • Service sshd sur Rocky, ssh sur Ubuntu. Port 22 implicite, comme 80 pour HTTP et 443 pour HTTPS.
