Pare-feu firewalld

Une phrase à retenir : je choisis d'abord la zone, puis ce que j'autorise, puis si le changement est temporaire ou permanent.

Runtime et permanent — la notion centrale

Runtime — en mémoire
Permanent — sur le disque
La commande
sudo firewall-cmd --add-service=http
sudo firewall-cmd --permanent --add-service=http
sudo firewall-cmd --reload
Effet
immédiat
écrit, actif seulement après le --reload
Ce qui l'efface
un --reload ou un redémarrage — d'où le filet de sécurité en labo
rien : c'est la configuration de référence

Sens des deux commandes : --runtime-to-permanent mémoire → disque (j'ai testé, j'enregistre) · --reload disque → mémoire, et écrase ce qui n'était pas enregistré.

Les commandes — toutes en sudo firewall-cmd …

--state le pare-feu tourne-t-il (seul sans sudo)
--list-all toute la configuration de la zone
--get-default-zone zone par défaut
--get-active-zones zones réellement actives
--get-zones toutes les zones existantes
--set-default-zone=work changer la zone
--zone=public --add-port=9001/tcp
--zone=public --remove-port=9001/tcp
--zone=public --add-service=http
--zone=public --remove-service=ssh
--permanent --zone=trusted
--add-source=192.168.1.0/24
--runtime-to-permanent enregistrer mes tests

Tout passe par sudo, même les lectures : seul --state répond sans privilège. Rattacher durablement une interface à une zone : plutôt nmcli connection modify ens18 connection.zone public.

L'exception : créer une zone

sudo firewall-cmd --permanent --new-zone=lodhi # obligatoire sudo firewall-cmd --reload # la charge en runtime

Sans --permanent, firewalld refuse : cette option n'est pas permise en runtime.

Les pièges qui coûtent des points
  • --reload efface les règles runtime non enregistrées. Enregistre avant de recharger.
  • Retirer ssh ne coupe pas ta session en cours : firewalld laisse vivre les connexions établies. C'est la prochaine connexion qui sera refusée — et tu ne t'en aperçois qu'une fois dehors.
  • --add-port=9001 sans /tcp est refusé, et autoriser un service ne le démarre pas : le pare-feu laisse passer, systemctl démarre.
  • Service actif, port en écoute, pare-feu ouvert, et ça ne passe toujours pas ? Quatrième gardien sur Rocky : getenforce → SELinux.
