Rocky 9 face à Ubuntu/Debian

Même travail, deux syntaxes. C'est la première cause d'erreur quand on suit les deux cours en parallèle : la commande est juste, la distribution est fausse.

Les équivalences à connaître

Besoin
Rocky 9 / RHEL
Ubuntu / Debian
Installer un paquet
sudo dnf install httpd
sudo apt-get install -y httpd
Rafraîchir l'index
sudo dnf makecache
(automatique avant chaque opération)
sudo apt-get update
Créer un compte
sudo useradd -m paul
sudo passwd paul
sudo adduser paul
(interactif, tout en une fois)
Groupe qui donne sudo
wheel
sudo
Unité systemd de SSH
sshd
systemctl status sshd
ssh
systemctl status ssh
Pare-feu
firewalld — firewall-cmd
zones, runtime / permanent
ufw — sudo ufw allow 22/tcp
ni zones, ni runtime
Réseau permanent
nmcli (NetworkManager)
netplan — /etc/netplan/*.yaml
Journal d'authentification
/var/log/secure
/var/log/auth.log
Journal général
/var/log/messages
/var/log/syslog
Dépôts déclarés dans
/etc/yum.repos.d/
/etc/apt/sources.list.d/
Dossier personnel par défaut
drwx------ (0700)
drwxr-x--- (0750)
/etc/ssh/sshd_config
-rw------- (600) — sudo requis
-rw-r--r-- (644) — lisible par tous

Ce qui ne change pas

ip a ip route ssh scp systemctl journalctl grep find tar chmod chown lsblk mount — et le processus s'appelle sshd des deux côtés, même quand l'unité s'appelle ssh.

Le piège le plus fréquent
$ systemctl status ssh Unit ssh.service could not be found.
Tu es sur Rocky : l'unité s'appelle sshd. Le même réflexe inversé sur Ubuntu donne « Unit sshd.service could not be found ». Avant de taper, regarde quelle machine tu as en face.
